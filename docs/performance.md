# สมรรถนะและวิธีวัด

ค่าด้านล่างวัดบน macOS arm64, Node 24.13.0 ด้วย `node scripts/perf/world.mjs` โดยใช้โลกที่สร้างจาก seed คงที่ วอร์มหนึ่งรอบ วัดสามรอบ และรายงานมัธยฐาน วัดโค้ดเดียวกับเกมและตรวจ checksum ของผลลัพธ์

| งาน | ก่อน | หลัง | ผลลัพธ์ |
|---|---:|---:|---:|
| ตรวจชนทั้งตาราง 4,600 × 3,000 ที่ช่องห่าง 40 | 778.2 ms | 35.1 ms | 668 จุดชนเท่าเดิม |
| ตรวจเส้นทางมนุษย์ แมว กระต่าย ใน 4 seed | 3,106.2 ms | 136.2 ms | ผ่าน 12 กรณีเท่าเดิม |

ผลบนเครื่องอื่นเปลี่ยนได้ จึงใช้เป็น baseline สำหรับเปรียบเทียบในเครื่องเดียวกัน ไม่ถือเป็นตัวเลข FPS หรือเวลาโหลดหน้าเกม ใช้ `node --cpu-prof --cpu-prof-dir=reports scripts/perf/world.mjs` เพื่อเก็บ CPU profile เมื่อการเปลี่ยนแปลงครั้งต่อไปทำให้ช้าลง `reports/` ถูก ignore จาก Git

ชุดทดสอบเต็มลดจาก **834.9 วินาทีเหลือ 24.6 วินาที** และผ่าน 41 ชุดเท่าเดิม หลังแก้เส้นทางและรัน 2 process พร้อมกัน ชุดเร็ว 23 ชุดใช้ 2.4 วินาที ค่าเวลาเป็นผลรวมของงานหลายอย่าง จึงไม่ใช้แทน benchmark ของ `blockedAt` โดยตรง

## ต้นเหตุและการแก้

`src/world/rooms.js#blockedAt` เดิมค้น feature ทั้ง 270 รายการหลายครั้งต่อจุด และกรณี fissure/trench ยังค้นทั้งรายการซ้อนใน callback ตอนตรวจเส้นทางจะเรียกฟังก์ชันนี้ซ้ำหลายพันครั้ง ตอนนี้กรองเฉพาะ feature ที่ทับจุดก่อน แล้วใช้ชุดเล็กนั้นตอบเรื่องสะพาน ใย และเมล็ดที่วางไว้ การเช็กกรอบสี่เหลี่ยมก่อนคำนวณระยะช่วยตัด feature ที่อยู่ไกล ค่าเชิงพฤติกรรมยังผ่านชุด `routes`, `roster`, และชุดสัตว์

`validateRoute` เดิมคำนวณ `waterAt` ทุกช่องแม้ร่างไม่ใช่ปลา จึงเปลี่ยนให้คำนวณเมื่อจำเป็น BFS สองตัวใน production ใช้ดัชนีหัวคิวแทน `shift()` เพื่อลดการเลื่อนข้อมูลทั้งหมดทุกครั้ง

## งานที่ควรติดตาม

ชุดทดสอบสัตว์หลายไฟล์ยังมี grid/BFS ซ้ำภายใน test เพื่อพิสูจน์ว่าเดินถึงเป้าหมายได้ หากต้องเพิ่มสถานการณ์อีกมาก ควรย้ายตัวช่วยสร้าง grid ของ test ไปไว้ `tests/helpers/` โดยต้องคง assertion ต่อพฤติกรรมเดิม การเร่ง suite เพิ่มควรเก็บ CPU profile ก่อนทุกครั้งเพื่อแก้ตรงจุด และวัดหลังแก้พร้อม checksum/ชุดเส้นทางเดิม

หน้า production สร้างด้วย Vite เป็น JS/CSS ที่ minify และมีชื่อไฟล์ตาม hash; `npm run build:check` ยืนยันว่า HTML ชี้ไปยังไฟล์ใน `dist/` จริง ขนาดโดยรวมและ gzip พิมพ์จากตัวตรวจ build ระยะเวลาโหลดจริงขึ้นกับเครือข่ายและ browser ควรวัดด้วย browser profiler ก่อนตัดสินใจย้ายงาน render/โลกไป worker
